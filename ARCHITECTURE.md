# Architecture

SwiftUI views bind to one window-owned `@MainActor` coordinator. Sidebar destinations observe that shared coordinator, so navigation cannot cancel or lose active analysis/download tasks. The coordinator owns explicit task cancellation and receives ordered progress events; views never own network task lifetimes. It validates intent and calls injected provider/services but does not parse HTML or own networking. `MultiSiteProvider` routes an already exact-host-validated source to `AO3Client` or `FanFictionClient`; both obtain a cancellation-aware full lifecycle lease from the same `AO3RequestScheduler` actor, so metadata, chapter, and file requests cannot overlap across providers. Courtesy and parsed `Retry-After` cooldowns are published to `UserDefaults`, survive relaunches, and are capped to avoid an unbounded hostile delay. Transport failures are converted to actionable offline/timeout categories without logging request data. `HTTPTransport` is replaceable in tests. Provider-specific SwiftSoup parsers semantically parse bounded HTML. Downloads are staged, verified, then moved to a collision-safe destination.

The user-facing product name is ArchiveBind, while the original target name, bundle identifier, Application Support location, managed PDF markers, and hidden source-folder names remain compatible with earlier builds. The New Download destination explicitly clears only idle Library-view context; it never clears an active operation or persistent Library records.

The app is sandboxed for outbound networking and user-selected folder access. Adult-warning consent is an explicit local preference; enabled work analyses add only AO3's `view_adult=true` parameter. A post-redirect response must stay on its exact provider host and retain the requested work/story ID; FanFiction.net also retains the requested chapter number. Browser/login cookies are not imported and verification pages are not bypassed. AO3 series downloads and bulk retries are sequential and preserve selected author order. FanFiction.net stories are also fetched sequentially, sanitized to a conservative formatting whitelist, and assembled locally as valid EPUB 3, navigable PDF, or standalone HTML. Every verified output, AO3 series part, and failure is checkpointed in the versioned, atomic `LibraryStore`, together with a security-scoped destination bookmark. The store validates its schema, atomically replaces the primary file, and keeps a separately validated last-known-good recovery copy. Combined-only AO3 jobs retain verified source books in a hidden project folder so future retry, metadata editing, and recombination do not require another network request.

`EPUBMerger` extracts verified inputs into application staging, reads container/OPF manifests and spines, namespaces resources, and writes a new EPUB 3 package. It adds reflowable title/Contents/part-divider front matter and emits one shared hierarchical navigation model for both the visible Contents and reader navigation. `PDFMerger` inserts original PDFKit body pages without rasterization, imports source bookmark hierarchies, and generates marked title/Contents pages with internal link annotations, page numbers, and a matching PDF outline. Marked front matter is replaced rather than nested on later metadata edits. Automatic assembly occurs only when the final selected subset is complete. Other failures remain retryable and no longer block combining a complete subset. `BookMetadataEditor` updates EPUB packages atomically and uses PDFKit for PDF metadata and managed front matter. All downloaded markup and ebooks are treated as untrusted data.
